Partner API

Other systems can issue certificates automatically

For example, LMSpromise the moment a learner completes a course.

One key per system

Admins create and revoke keys with chosen permissions. Each key sees only its own certificates.

Approval stays in control

An approver reviews each one unless an admin trusts the system. Revoking always needs a person.

Students handled for you

Send a student ID: Certyfi creates the student, emails them, and can take payment first.

Instant updates

Certyfi tells the system the moment a certificate is paid, issued or revoked, signed and retried.

Montessori360 could do the same at the end of a school year. Published interactive documentation is at certyfi.ahamsys.com/api/v1/docs, and each system is rate-limited separately. A repeated request returns the same certificate instead of issuing a duplicate, so systems can retry safely. Because revoking is permanent, a connected system can only ask for a revocation; staff approve it on the Revoke & suspend page. A system can also cancel a request it made before it's issued. The instant updates are signed webhooks, retried for about a day if the system is down; staff see each delivery on the API keys page. Each system can also show its users what a template looks like through a short-lived preview link.
