How it works

Security & Trust

Verification checks the record, not the document

A tampered PDF or image is easy to spot the moment someone checks it — Certyfi never asks a verifier to trust the file in front of them, only what the platform itself reports back.

LAYER 1
The document isn't the proof

Every certificate resolves back to its real record by credential ID. Editing a downloaded PDF or image changes nothing — verification always checks the source of record, not the file.

LAYER 2
A tamper-evident history

Every action — issued, approved, suspended, revoked — is recorded in a hash-chained ledger. Altering any past entry breaks every entry that follows it, so history can't be quietly edited.

LAYER 3
Cryptographic signing

Each institution has its own signing key, and every approved certificate is signed with it. The verify page can check the signature locally in the visitor's browser, so authenticity never depends on trusting Certyfi's answer.

LAYER 4
Bitcoin anchoring

The ledger's latest state is periodically timestamped to the Bitcoin blockchain using the open OpenTimestamps protocol. Once confirmed, rewriting history would mean rewriting Bitcoin — and each certificate offers a downloadable proof anyone can verify with standard open-source tools.
